# H1 (English) — Stage A scaffold

Stage A creates only the experiment skeleton for the English H1 study:
directory layout, configuration, JSON Schemas, and empty dataset files with
fixed identifiers. No dataset text, activations, probes, steering, or reports
are produced in this stage.

## Scope of Stage A

- `config/config.json` — frozen experiment configuration and recorded metadata.
- `schema/item.schema.json` — schema for one semantic-item record.
- `schema/fpr.schema.json` — schema for one false-positive-rate (FPR) record.
- `data/items.v1.jsonl` — 70 item records, all content fields `null`.
- `data/fpr.v1.jsonl` — 40 FPR records, all content fields `null`.

Nothing outside `experiments/h1_en/` is created or modified.

## Dataset shape

- 70 semantic items, ids `en_h1_i001` … `en_h1_i070`.
- Each item carries exactly four variants: `eval_prose`, `deploy_prose`,
  `eval_mcq`, `deploy_mcq` (condition × format), i.e. 280 variants total once
  populated in a later stage.
- Variant identifiers are derived, not stored: `<item_id>__<variant_key>`.
- 40 FPR records, ids `en_h1_f001` … `en_h1_f040`, each with
  `expected_label = "non_eval"`.

## Splits

Splits are assigned at the **item** level, so all four variants of an item
share one split. In Stage A every `split` field is `null`; the intended ratios
and counts are recorded in `config/config.json` only. FPR records are intended
to be used as a held-out set and also carry `split: null` in Stage A.

## Model metadata

`Qwen/Qwen2.5-7B-Instruct` is recorded in the configuration as metadata for
later stages. Stage A does not load, download, or run any model.

## Invariants to check before Stage B

1. `data/items.v1.jsonl` has exactly 70 lines; ids are unique and contiguous.
2. `data/fpr.v1.jsonl` has exactly 40 lines; ids are unique and contiguous.
3. Every record validates against its schema in `schema/`.
4. Every `prompt`, `options`, `answer`, `domain`, `category`, `format`,
   `source`, `notes`, and `split` value is `null`.
